# Спецификация: Рекурсивное отслеживание файловой системы

## Контекст

Текущая реализация файлового дерева в eTty использует `fs.watch` для отслеживания изменений файловой системы, но только для директорий, которые явно открыты в дереве (lazy-load). При изменении директории вне дерева (через терминал) изменения не отображаются до ручного обновления.

Необходимо обеспечить постоянное отслеживание всех изменений в корневой папке проекта (текущей рабочей директории активной вкладки терминала) и во всех дочерних папках, чтобы UI файлового дерева всегда отображал актуальное состояние ФС.

## Требования

### REQ-1: Отслеживание корневой директории
- При установке корневой директории для файлового дерева (через `fs:set-root` или автоматически через OSC 7) должен создаваться `fs.watch` watcher для этой директории
- Watcher должен отслеживать все события: создание, удаление, переименование файлов и папок

### REQ-2: Рекурсивное отслеживание
- При раскрытии (expand) папки в дереве файлов для неё должен создаваться watcher
- При сворачивании (collapse) папки watcher должен удаляться (оптимизация ресурсов)
- При создании новой папки через UI или обнаружении через watcher — автоматически начинать отслеживание

### REQ-3: Синхронизация с терминалом
- При смене директории в терминале (через `cd`, OSC 7) корневая директория дерева должна обновляться
- При смене вкладки — корневая директория должна соответствовать CWD активной вкладки
- Состояние watchers должно очищаться при смене корневой директории

### REQ-4: Обработка событий
- События `rename` (создание/удаление/переименование) должны корректно обновлять дерево
- События `change` (изменение файла) должны обновлять метаданные (размер, mtime) если файл видим
- Debounce 300ms для предотвращения флуда событий

### REQ-5: Производительность
- Максимальное количество активных watchers: 100 (лимит для защиты от перегрузки)
- При превышении лимита — логировать warning и отслеживать только корневую директорию
- Удаление watchers при сворачивании папок для экономии ресурсов

### REQ-6: Обработка ошибок
- При ошибке создания watcher (например, нет прав) — логировать warning, не падать
- При `ENOENT` (файл удалён во время операции) — корректно обработать, не крэшить
- При EMFILE (слишком много открытых файлов) — отключить watchers с нижнего уровня, сохранить корневой

## Ограничения

- Не отслеживаем симлинки (-followSymlinks: false) для избежания циклов
- Не поддерживаем сетевые ФС (NFS, SMB) — поведение не гарантировано
- macOS FSEvents vs Node fs.watch — используем стандартный Node API
- Не отслеживаем изменения содержимого файлов (только структуру директорий)

## Макеты и референсы

Не применимо — изменения только в логике, UI остаётся без изменений.

## Переиспользуемые решения

- `src/main/file-manager.js` — класс FileManager с методами `watchDirectory`, `unwatchDirectory`
- `src/renderer/file-tree.js` — класс FileTree с обработкой `fs:dir-changed`
- `src/preload/index.js` — IPC API для fs:watch-dir, fs:unwatch-dir
- Существующий debounce 300ms в `file-tree.js`

## Затронутые файлы

- `src/main/file-manager.js` — доработка логики watchers (рекурсивное отслеживание, лимиты)
- `src/renderer/file-tree.js` — управление watchers при expand/collapse, смене корня
- `src/main/index.js` — возможно, передача CWD между tab → file-manager

## Критерии приёмки

- [ ] При открытии папки в терминале дерево показывает актуальное содержимое без ручного обновления
- [ ] При создании файла через терминал (`touch file.txt`) — он появляется в дереве в течение 300ms
- [ ] При удалении файла через терминал (`rm file.txt`) — он исчезает из дерева в течение 300ms
- [ ] При переименовании папки — дерево обновляется корректно
- [ ] При сворачивании папки watcher удаляется (проверить через lsof или аналог)
- [ ] При смене вкладки watchers очищаются и создаются для новой CWD
- [ ] При превышении 100 watchers — warning в консоли и ограничение на корневую директорию
- [ ] Нет утечек памяти при долгой работе (проверить через DevTools Memory)
