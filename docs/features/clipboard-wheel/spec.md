# Спецификация: Буфер обмена в колесе команд (mobile)

## Контекст

Мобильный терминал (`mobile/`, Flutter, `xterm`) не умеет работать с системным буфером обмена:
в `lib/` нет ни одного `Clipboard.getData`/`Clipboard.setData`. Системная «Вставить» из тулбара
клавиатуры приходит в `CustomTextEdit.updateEditingValue → _onInsert → terminal.textInput()`, то
есть **без bracketed paste** (многострочный текст прилетает как набранный руками, переводы строк
срабатывают как Enter), а `keyboardType: visiblePassword` на части устройств вообще прячет кнопку
вставки. Копирования выделения тоже нет: long-press выделяет слово, но результат никуда не уходит.
Отдельно: копирование, которое инициирует само TUI-приложение через `OSC 52` (tmux copy-mode,
vim с `clipboard=unnamed`), тоже теряется — `OscTap` его разбирает, но `TabController
.onClipboardWrite` в UI не подключён, колбэк всегда `null`.

Место для фичи — уже существующее «Колесо своих команд» (`TerminalGestureLayer`,
`_onTwoFingerDoubleTap`): двойной тап двумя пальцами открывает двухуровневое меню
(группы → команды), команда вставляется через `terminal.paste(text)` — с bracketed paste, если
приложение его включило. Выбранный подход (согласован): **встроенная группа «Буфер»** внутри этого
колеса, первым сектором в корне, а не отдельные сектора рядом с пользовательскими группами.

## Требования

### Модель

- **REQ-1.** `QuickCommand` получает `kind` (`QuickCommandKind.text | copy | paste`, по умолчанию
  `text`). Существующие конструкторы и `copyWith` работают без изменений; `copyWith` сохраняет
  `kind`. В JSON `kind` не пишется и не читается: действия может объявить только код, не конфиг.
- **REQ-2.** `QuickCommandsDefaults.clipboardGroup` — константная группа `id: 'g-clipboard'`,
  `label: 'Буфер'`, команды: `📋 Вставить` (`paste`) и `⧉ Копировать` (`copy`).
- **REQ-3.** Композиция колеса — функция `QuickCommandsDefaults.withClipboard(groups)`:
  `[clipboardGroup, ...groups]`. Вызывается в `TerminalPage` при передаче `commandGroups` в
  `TerminalGestureLayer`. `quickCommandsProvider`, `decodeQuickCommands` и экран настроек не
  меняются: «Буфер» не хранится в `AppSettingsStore` и не редактируется.

### Поведение колеса

- **REQ-4.** Корень колеса команд = «Буфер» (сектор 0, 12 часов) + пользовательские группы в их
  порядке. Пользовательских групп нет → колесо сразу открывается на уровне команд «Буфера»
  (существующее правило «одна группа — сразу внутрь»), то есть двойной тап даёт вставку за один тап.
- **REQ-5.** Подсказка «Нет быстрых команд…» больше не показывается: «Буфер» есть всегда. Проверка
  пустоты остаётся защитой от программной ошибки, но в обычном потоке недостижима.
- **REQ-6.** Выбор команды: `text` → `terminal.paste(command.text)` (как сейчас); `paste` →
  `Clipboard.getData(Clipboard.kTextPlain)` → `terminal.paste(text)`; `copy` → текущее выделение
  `TerminalController.selection` → `terminal.buffer.getText(selection)` → `Clipboard.setData`.
- **REQ-7.** Пустой/отсутствующий буфер обмена (`paste`) — снек «Буфер обмена пуст», в канал ничего
  не уходит. Нет выделения (`copy`) — снек «Нет выделения: выделите текст long-press», в буфер
  ничего не пишется. Ошибка платформенного канала (`PlatformException`) ловится и показывается
  снеком, крэша нет.
- **REQ-8.** Копирование даёт снек «Скопировано: N симв.» и снимает выделение; вставка снека не
  показывает (видно по выводу в терминале).
- **REQ-9.** Открытие колеса команд **не сбрасывает выделение** (сейчас `_onTwoFingerDoubleTap`
  вызывает `clearSelection`) — иначе копировать нечего: long-press → двойной тап → «Копировать».
  Открытие колеса быстрых действий (три пальца) по-прежнему сбрасывает выделение.

### Копирование изнутри TUI (OSC 52)

Копирование, которое приложение запускает само (tmux copy-mode с `set-clipboard on`, vim с
`clipboard=unnamed`, любые TUI, пишущие `OSC 52`), обязано попадать в системный буфер обмена.
Разбор уже готов и тестирован: `OscTap` вынимает `OSC 52` из вывода ДО `terminal.write()`,
включая DCS-passthrough `\x1bPtmux;\x1b\x1b<payload>\x1b\\`; tmux-конфиг хуков уже содержит
`set -s set-clipboard on`, `set -as terminal-features ',*:clipboard'` и `allow-passthrough on`.
Не хватает одного звена: `TabController.onClipboardWrite` в `TerminalPage._addTab` не передаётся,
поэтому колбэк всегда `null` и `OSC 52` молча теряется.

- **REQ-10.** `TerminalPage._addTab` передаёт `onClipboardWrite` в `domain.TabController`;
  обработчик — общий хелпер записи в системный буфер (`Clipboard.setData`, `kTextPlain`), тот же,
  что использует «Копировать» колеса. Хелперы буфера (чтение/запись, ловля `PlatformException`)
  живут в `lib/platform/system_clipboard.dart` — без SSH и без домена, чтобы тестироваться
  напрямую.
- **REQ-11.** Семантика — как у десктопа (`src/renderer/features/terminal/terminal-osc-handler.js`):
  непустой payload → запись текста; пустой payload → очистка буфера (запись `''`); `Pt == '?'`
  (запрос чтения) — игнор, содержимое буфера устройства наружу не отдаётся; битый base64/UTF-8 —
  игнор (уже в `OscTap`).
- **REQ-12.** Запись асинхронная и молчаливая: снеков/вибрации нет (TUI может обновлять буфер
  часто — tmux copy-mode при каждом движении в выделении). `PlatformException` ловится и
  логируется, канал не рвётся, UI не падает.
- **REQ-13.** Запись в буфер не зависит от колеса и от выделения xterm: работает и в tmux-режиме,
  и в обычном SSH, на любой вкладке (колбэк пер-вкладочный, как `onCwdChange`).

### Документация

- **REQ-14.** `mobile/README.md` (раздел про жесты/колёса): «Буфер» в колесе команд, что
  копирование требует предварительного выделения long-press, и что `OSC 52` из TUI-приложений
  попадает в системный буфер. `docs/plans/mob/plan.md` — новый пункт REQ-24 со ссылкой на эту
  спецификацию.

## Ограничения и не-цели

- Не трогаем `KeyBar`, колесо быстрых действий, системную вставку из тулбара клавиатуры
  (`CustomTextEdit`) и копирование по long-press без колеса.
- Буфер только в одну сторону по инициативе удалённой стороны: `OSC 52` пишет, но не читает —
  `Pt == '?'` остаётся игнором, как на десктопе. Ограничения размера payload нет (как на десктопе).
- Никаких подтверждений для многострочной вставки: bracketed paste делает своё дело, размер не
  ограничиваем (поведение совпадает с уже существующими командами колеса).
- `QuickActionsConfig.maxGroups`/`maxCommandsPerGroup` не меняются: «Буфер» вне пользовательских
  лимитов и не занимает сектора в настройках.
- Формат `quickCommands` в хранилище не меняется — миграции нет.

## Тесты

- `test/domain/quick_commands_test.dart` — `withClipboard` (порядок, идемпотентность),
  `kind` в `copyWith`, JSON без `kind` читается как `text`.
- `test/ui/terminal/terminal_gestures_test.dart` — буфер мокается через
  `TestDefaultBinaryMessengerBinding` (`Clipboard.getData`/`setData`): вставка из буфера уходит
  в канал; пустой буфер → снек и пустой канал; копирование выделения пишет в буфер и снимает
  выделение; без выделения → снек, буфер не тронут; «Буфер» первым сектором корня; при отсутствии
  пользовательских групп колесо открывается сразу на «Вставить»/«Копировать»; существующий тест
  «без команд двойной тап показывает подсказку» переписывается на новое поведение.
- `test/ui/settings/quick_commands_screen_test.dart` — «Буфер» в редакторе не появляется.
- `test/platform/system_clipboard_test.dart` — чтение/запись через мок платформенного канала,
  пустой и `null` текст, `PlatformException` не пробрасывается.
- `test/domain/tab_controller_test.dart` — `OSC 52` из вывода доходит до `onClipboardWrite`
  (непустой текст и пустой payload), байты `OSC 52` в `output` не попадают; `Pt == '?'` колбэк не
  вызывает. Тот же путь — с DCS-обёрткой tmux (уже покрыто в `osc_tap_test.dart`, здесь важно, что
  колбэк контроллера действительно прокинут).
- Связка `_addTab → onClipboardWrite` проверяется в виджетном тесте `TerminalPage` только если он
  уже существует к моменту реализации; иначе достаточно ручной проверки в tmux copy-mode и
  типизированного `onClipboardWrite: writeSystemClipboard` (компилятор ловит потерю аргумента).
