# План реализации: Настройка размера статусбара

## Обзор

Небольшая фича из 5 изменений. Все задачи последовательные (каждая зависит от предыдущей, так как строятся поверх существующего паттерна).

## Задачи

### Блок 1 — Core & Config (последовательно)

| # | Задача | Файлы | Зависит от | Режим выполнения | Проверка |
|---|--------|-------|------------|------------------|----------|
| 1 | Добавить `statusBarSize` в конфиг по умолчанию | `src/main/config-loader.js` | — | sequential | Чтение кода: default вернёт поле |
| 2 | Добавить константы размеров в `ui-dimensions.js` | `src/renderer/core/config/ui-dimensions.js` | — | sequential | Чтение файла |
| 3 | Добавить CSS-правила `data-size` | `src/renderer/styles.css` | 1,2 | sequential | Визуально: inspect element показывает data-size |
| 4 | Добавить подписку StateStore/EventBus и инициализацию в `index.js` | `src/renderer/index.js` | 3 | sequential | Переключение меняет data-size атрибут |
| 5 | Добавить UI-строку в настройки | `src/renderer/settings-page.js` | 4 | sequential | В настройках виден select, переключение работает |
| 6 | Обновить CHANGELOG.md | `CHANGELOG.md` | 5 | sequential | Файл содержит запись |

## Стратегия выполнения

Все задачи идут строго по порядку 1→2→3→4→5→6.
Причина: каждая следующая использует результат предыдущей (UI не имеет смысла без подписок, подписки — без CSS, CSS — без констант/конфига).

## Ревью после каждого шага

- После каждой задачи — сверка с `plan.md` и `spec.md`.
- Проверка отсутствия конфликтов с параллельными задачами (в данном плане — нет параллельных).
- После задачи 5 — ручная проверка dev-режима: golden path + edge cases.
