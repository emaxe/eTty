# Стартовый промпт для реализации фичи «Подсветка git diff»

Скопируй целиком и вставь в новую сессию.

---

Реализуй фичу **Подсветка git diff** по подготовленной документации.

## Документация

- Спецификация: `docs/features/git-diff-highlight/spec.md` — прочитай перед началом
- План: `docs/features/git-diff-highlight/plan.md` — следуй порядку задач, секциям «Стратегия выполнения» и «Ревью после каждого шага»
- Чеклист: `docs/features/git-diff-highlight/checklist.md` — отмечай прогресс

## Инструкции

1. Прочитай `spec.md`, `plan.md` и `checklist.md` целиком.
2. Прочитай `AGENTS.md` — там описаны архитектурные инварианты проекта (DI, EventBus, StateStore, IPC_CHANNELS, Config, Cleanup, Адаптер). Все они обязательны.
3. Создай ветку `feature/git-diff-highlight` и переключись на неё: `git checkout -b feature/git-diff-highlight`.
4. Отметь в checklist.md пункты «Подготовка» как выполненные.
5. Выполняй задачи строго по стратегии выполнения из plan.md:
   - Задачи #1 → #2 → #3 → #4 строго последовательно
   - Задачи #5 и #6 — после #4, можно параллельно субагентам (разные файлы)
6. После каждой задачи:
   - Сверься с `plan.md` и `spec.md` (скоуп, критерии приёмки)
   - Убедись, что имена EventBus-событий (`git:status-updated`, `editor:file-saved`) и ключей StateStore (`git.isRepo`, `git.rootPath`, `git.fileStatuses`) совпадают во всех компонентах
   - Если задачу делал субагент — проверь: нет ли `window.electronAPI` напрямую, есть ли `destroy()` с отпиской
7. Отмечай выполненные задачи в checklist.md (`[x]`).
8. Запускай проверку, указанную для задачи в plan.md.
9. Коммить после каждого блока: после Блока 1, после Блока 2, после Блока 3.
10. По завершении — отметь «Финализация» в checklist.md и обнови статус в README.md на `Done`.
11. Если что-то непонятно — спроси, не додумывай.

## Ключевые архитектурные ограничения

- Все IPC-вызовы — через `this._api` (ElectronApiAdapter), не через `window.electronAPI` напрямую
- Все IPC-каналы — через константы из `shared/ipc-channels.js` (GIT_GET_STATUS, GIT_GET_DIFF, GIT_GET_ROOT)
- Коммуникация между компонентами — только через EventBus
- Polling-интервал — из `APP_CONFIG.GIT_STATUS_POLL_INTERVAL`, не инлайн
- Каждый компонент с подписками имеет `destroy()` с отпиской
- Базовая ветка для merge: `main` (не менять без необходимости; по ней скилл feature-accept подставит цель слияния)
