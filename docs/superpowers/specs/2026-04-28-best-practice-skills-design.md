# Спецификация: Best Practice Skills & Documentation

**Дата:** 2026-04-28
**Статус:** Approved

## Контекст

Проект eTty прошёл масштабный рефакторинг (Блоки 1–4): DI Container, EventBus, StateStore, IPC handlers split, AppService. Архитектурные принципы зафиксированы, но не формализованы в виде автоматических проверок. Существующие скиллы (`feature-planning`, `feature-accept`) покрывают цикл планирования и приёмки фичи, но между ними отсутствуют:

1. Процесс code review с привязкой к архитектурным инвариантам проекта
2. Лёгкий процесс для багфиксов (без тяжёлого feature-planning)
3. Явные чеклисты для типовых изменений (новый компонент, новый IPC handler)
4. Implementation guard — правила, которые агент соблюдает при любом изменении кода

## Требования

### REQ-1: Чеклисты для типовых изменений

Создать файлы в `.agents/rules/checklists/`:

- `new-component.md` — чеклист для нового UI-компонента
- `new-ipc-handler.md` — чеклист для нового IPC-обработчика
- `new-feature.md` — общий чеклист для новой фичи
- `code-quality.md` — чеклист качества кода (используется скиллом code-review)

Каждый чеклист — самодостаточный документ с пронумерованными проверками.

### REQ-2: Implementation Guard в AGENTS.md

Добавить в `AGENTS.md` секцию «Правила реализации» с:

- Ссылками на чеклисты по типу изменения
- Архитектурными инвариантами (DI, EventBus, StateStore, IPC_CHANNELS, config/, destroy(), адаптер electronAPI)

Секция читается агентом автоматически в начале каждой сессии.

### REQ-3: Скилл code-review

Файл: `.agents/skills/code-review/SKILL.md`
Триггер: `/code-review` (ручной вызов).

Процесс:
1. Определить изменённые файлы (`git diff --name-only`)
2. Прочитать `code-quality.md`
3. Определить типы изменений → прогнать специализированные чеклисты
4. Вывести отчёт: пройдено / замечания с файлами и строками
5. Предложить автофикс при возможности

### REQ-4: Скилл bugfix

Файл: `.agents/skills/bugfix/SKILL.md`
Триггер: `/bugfix` (ручной вызов).

Процесс:
1. Описание бага (от пользователя или аргумент)
2. Воспроизведение: шаги, затронутые файлы
3. Диагностика: Explore-агент ищет причину
4. Фикс: реализация с соблюдением архитектурных инвариантов
5. Проверка: `npm run build` + ручная проверка + быстрый прогон code-quality.md
6. Коммит: предложить `fix:` коммит

Без docs/features/, без starter-prompt. Лёгкий процесс.

### REQ-5: Доработка project-rules.md

Дополнить существующий файл:
- Секция «Чеклисты» со ссылками на `.agents/rules/checklists/*.md`
- Расширить «Правила работы с кодом» (DI, EventBus, StateStore, destroy(), адаптер)
- Секция «Скиллы проекта» — список скиллов с описанием когда вызывать

### REQ-6: Обновление AGENTS.md

Добавить:
- Секцию «Правила реализации» (REQ-2)
- Секцию «Скиллы» с описанием всех 4 скиллов проекта
- Ссылки на чеклисты

## Ограничения

- Не менять существующий контент `project-rules.md` — только дополнять
- Не менять существующие скиллы (`feature-planning`, `feature-accept`)
- Язык документации — русский (код и пути — как в проекте)
- Скиллы совместимы с форматом `.agents/skills/*/SKILL.md`
